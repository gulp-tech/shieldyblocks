# HyperTNT + PurpurBedrock: пакет для разработчика ядра

Это материалы для проектирования и проверки интеграции, а не готовое решение. Пакет предметов экспериментальный и не проверен на сервере или клиенте. Установленный и подожжённый TNT им пока не изменяется.

## Содержимое архива

- `plugin/HyperTNT-2.1.0.jar` — JAR, предоставленный владельцем в `main`; не доказано, что именно этот файл установлен на сервере. SHA-256: `ce04cbcef588a92a78f83f35cde9b131d270106a8df55055199912dd603937a4`.
- `plugin/HyperTNT-src.zip` — предоставленные исходники 2.1.0, частично восстановленные декомпиляцией. Они успешно собираются и тест реестра прошёл; полная эквивалентность JAR не установлена. SHA-256: `1cc0a3ce9a00e40e0368baeb3134b246126b1cd06d4c6679640c430cd2e2f1ac`.
- `bedrock/resource_pack/` — исходники подготовленного RP: иконки предметов, шесть исходных PNG и geo.json блоков из предоставленного Ultimate TNT (Minty). Геометрия и блоковые текстуры пока не зарегистрированы и на поставленные блоки не влияют.
- `bedrock/HyperTNT-Items.mcpack` и `bedrock/custom_mappings/hypertnt-items.json` — предварительный RP и Geyser item mapping формата 1. Работа конкретной версии Geyser не проверена.
- `test/HyperTNT-Bedrock-ITEMS-TEST.zip` — отдельно размеченный тестовый набор: RP, mapping и шесть пользовательских конфигов TNT с изменённым только `custom_model_data`. В архиве есть инструкция по осторожной установке на тестовый сервер.

Файлы реестра установленных TNT, базы регионов и данные игроков в этот комплект намеренно не включены. Полный исходный аддон владельца: https://github.com/gulp-tech/shieldyblocks/blob/main/Ultimate_TNT_addon.mcaddon

## Типы

ID — ключ верхнего уровня в YAML, а не имя файла. В частности, `tnt_basic.yml` содержит ID `tnt`.

| HyperTNT ID | Файл | Из аддона | custom_model_data |
| --- | --- | --- | ---: |
| `tnt` | `tnt_basic.yml` | `power_tnt` | 710101 |
| `tnt_fire` | `tnt_fire.yml` | `blaze_tnt` | 710102 |
| `tnt_obs` | `tnt_obs.yml` | `deepslate_tnt` | 710103 |
| `tnt_heavy` | `tnt_heavy.yml` | `mega_tnt` | 710104 |
| `tnt_explosive` | `tnt_explosive.yml` | `super_tnt` | 710105 |
| `tnt_poseidon` | `tnt_poseidon.yml` | `water_tnt` | 710106 |

Выбор текстур сделан по смыслу и может быть изменён владельцем. Значения model data нужно проверить на конфликты с другими mappings.

## Задача

Показать соответствующие виды TNT Bedrock-игрокам в инвентаре, руке, выброшенными и установленными. Обычный TNT должен остаться без изменений. По возможности отдельно поддержать подожжённый TNT; если нельзя — явно описать ограничение.

Физический блок HyperTNT 2.1 — `Material.TNT`, тип хранится отдельно в `TntRegistry` по UUID мира и координатам. Поэтому статический mapping одинакового состояния Java TNT не отличит ванильный блок от кастомного. Посмотрите `TntListener.java` и `TntRegistry.java`: размещение, чистка записей при загрузке чанка, поршни и поджиг. Реестр и механика остаются источником истины HyperTNT, визуализация не должна изменять мир.

Нужен документированный совместимый механизм для передачи Geyser вида блока по конкретной координате без глобальной замены TNT и без замены настоящих блоков на другой материал. Предложите подходящий API/пакеты с указанием ограничений; не считайте предложенные имена методов или тип пакета заранее заданными. Укажите, как регистрировать модели/ресурсы до подключения клиента и как разрешаются runtime IDs. Проверьте поддержку Geyser custom item mappings и совместимость Bedrock-клиента, включая работу при установке блоков и существующих рецептов.

Интеграция должна учитывать появление и уход каждого клиента, загрузку/повторную отправку и выгрузку чанков, обновления блоков, смену измерения, перезаход и перезапуск, установку, разрушение, поджог, взрывы и поршни. Никаких призрачных блоков, побочных изменений обычного TNT, глобальных перезаписей других ванильных блоков или изменения механики защиты/взрывов. Если серверное API не может безопасно гарантировать что-либо, документируйте это и предложите альтернативу.

Просьба прислать API и пример использования плагином, исходники или патч ядра, тестовый JAR PurpurBedrock 26.2, точную версию встроенного Geyser, инструкцию установки, перечень ограничений и результаты испытаний с Bedrock-клиентом. Обязательно протестировать обычный TNT, все шесть видов, несколько игроков, перезаход, перезапуск, чанки, поршни, поджог и защиту WorldGuard/ShieldyBlocks.
