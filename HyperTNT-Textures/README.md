# HyperTNT — текстуры предметов Bedrock (частичная подготовка)

Этот предварительный пакет предназначен **только для предметов** (инвентарь, рука и выброшенный предмет) и **не меняет внешний вид TNT как установленного блока или подожжённой сущности**. В пакет также скопированы исходные текстуры и геометрия шести блоков для будущей интеграции; сами по себе они блоки не регистрируют и на внешний вид не влияют. Это не готовое решение для запроса «везде». На сервере и клиенте не тестировалось.

Изображения извлечены из предоставленного аддона Ultimate TNT (автор исходных текстур — Minty). Соответствие типов подобрано по смыслу:

## Предварительная установка для тестового сервера

1. Сохраните резервную копию существующих ресурсов и конфигов. Проверьте, что эти значения custom model data для `minecraft:tnt` не используются другими плагинами и не пересекаются с их mappings.
2. Положите `HyperTNT-Items.mcpack` в каталог `bedrock/packs/` вашей сборки PurpurBedrock (или папку `packs` Geyser на обычной сборке).
3. Положите `bedrock/custom_mappings/hypertnt-items.json` в `bedrock/custom_mappings/` (или папку `custom_mappings` Geyser).
4. В каждом файле `plugins/HyperTNT/tnts/tnt_<тип>.yml` измените только `item.custom_model_data` на соответствующее значение из таблицы. Не заменяйте целиком конфиги TNT и не изменяйте остальные параметры.
5. Полностью перезапустите сервер, перезайдите Bedrock-клиентом и получите новые предметы через HyperTNT. Уже выданные предметы не получат новый model data автоматически.
6. Проверьте, что обычный TNT и все шесть предметов выглядят правильно и размещаются/поджигаются как раньше. При неполадках удалите два добавленных файла и верните предыдущие значения `custom_model_data`.

Текстуры выбираются только для предмета `minecraft:tnt` с указанным непустым custom model data. Vanilla TNT без такой метки остаётся прежним. Версия встроенного Geyser должна поддерживать legacy custom item mappings; возможны несовместимости с конкретной сборкой PurpurBedrock.

## Осталось для полного решения

Установленный TNT и подожжённая сущность TNT не различаются ресурс-паком по данным предмета. Загруженные исходники HyperTNT 2.1 регистрируют тип установленного TNT отдельно по координатам, но физический блок остаётся обычным TNT. Статический Geyser mapping не умеет различать одинаковое состояние блока по координатам. Нужна отдельная интеграция, учитывающая реестр и обновления чанков/блоков, и проверка на конкретной сборке сервера и Bedrock-клиенте. Нельзя заменять все ванильные блоки TNT. Исходники 2.1 частично восстановлены декомпиляцией и ещё не проверены сборкой.
